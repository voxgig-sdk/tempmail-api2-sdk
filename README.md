# TempmailApi2 SDK

Spin up disposable email inboxes and read their messages via a simple HTTP API

> TypeScript, Python, PHP, Golang, Ruby, Lua SDKs, a CLI, an interactive REPL, and an MCP server for AI agents — all generated from one OpenAPI spec by [@voxgig/sdkgen](https://github.com/voxgig/sdkgen).

## About Tempmail API

[Tempmail.lol](https://tempmail.lol) is a disposable email service that lets you generate throwaway inbox addresses and fetch any mail they receive. This SDK targets the v2 HTTP API hosted at `https://api.tempmail.lol/v2`.

The API is built around three resources: available **domains**, generated **email** addresses, and the **inbox** of messages received for a given address. Typical use is to create a temporary address, hand it out to a sign-up form, then poll the inbox for the confirmation message.

Official client libraries exist for JavaScript and Python, and community support is available via the project's Discord. Consult the [API documentation](https://tempmail.lol/api) for current request shapes, authentication requirements, and any plan-based limits.

## Entities

The API exposes 3 entities:

| Entity | Description | API path |
| --- | --- | --- |
| **Domain** | The set of domain names that the service can issue temporary addresses under. | `/domains` |
| **Email** | A disposable email address generated by the API, used as the receive endpoint for incoming mail. | `/inbox/{token}/{emailId}` |
| **Inbox** | The collection of messages delivered to a disposable address, retrieved via the API for the address and token issued at creation time. | `/inbox/create` |

Each entity supports the following operations where available: **load**,
**list**, **create**, **update**, and **remove**.

## How it works

Every SDK call runs the same five-stage pipeline:

1. **Point** — resolve the API endpoint from the operation definition.
2. **Spec** — build the HTTP specification (URL, method, headers, body).
3. **Request** — send the HTTP request.
4. **Response** — receive and parse the response.
5. **Result** — extract the result data for the caller.

A feature hook fires at each stage (e.g. `PrePoint`, `PreSpec`,
`PreRequest`), so features can inspect or modify the pipeline without
forking the SDK.

### Features

| Feature | Purpose |
| --- | --- |
| **TestFeature** | In-memory mock transport for testing without a live server |

Pass custom features via the `extend` option at construction time.

### Direct and Prepare

For endpoints the entity model doesn't cover, use the low-level methods:

- **`direct(fetchargs)`** — build and send an HTTP request in one step.
- **`prepare(fetchargs)`** — build the request without sending it.

Both accept a map with `path`, `method`, `params`, `query`,
`headers`, and `body`. See the [How-to guides](#how-to-guides) below.
